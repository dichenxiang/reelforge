# 双人模式协议

## 谁决定什么

| 活儿 | 谁干 |
|---|---|
| 检索网页 / 读链接 / 抓资料 | **写稿 agent** |
| 写口播稿、写分镜 | **写稿 agent** |
| 工程、章节代码、配音、录屏、验收 | 执行 agent |
| 拍板 | 人 |

| 决策 | 谁拍板 | 执行 agent 能不能自己定 |
|---|---|---|
| 主题、参考与否、参考度 | 人 | ❌ 必须问 |
| 口播稿内容 | 写稿 agent 起草，人确认 | ❌ 人不点头不进工程 |
| 主题视觉（配色、风格库） | 人 | 可以给 2–3 个推荐，人选 |
| 章节分镜 | 执行 agent 起草 | 可以做，但第 1 章必须给人看 |
| 素材复用 vs 新生成 | 人 | 可以推荐，执行要问 |
| 录屏方式（人工/脚本） | 人 | 问一下 |
| 技术验收（ffprobe） | 机器 | ✅ 过了才算过 |

## 执行者最常见的三种跑偏

| 跑偏 | 表现 | 纠正 |
|---|---|---|
| 自己写稿 | 一上来就 `script.md` | 停，先 `duo.py handoff` |
| 自己检索 | 调 web_fetch / web_search 找资料 | 把链接写进交接稿，让写稿 agent 检索 |
| 跳过口播稿门 | 稿子没让人过就 scaffold | `duo.py intake` 会挡住 |

## 标准话术

**要写稿时**（执行 agent 对人说）：
```
我准备好写稿交接稿了（在 work/x/handoff.writer.md）。
请把整段粘给 Antigravity，它产出的 script.md / script.json / writer-notes.md
放回 work/x/，然后回我一声，我接着审参考度。
```

**收稿审完后**：
```
参考度 38/60（上限 60），结构借了「开场冲突 → 三点拆解 → 落点」。
请你看 work/x/script.md：
- 没问题回「过」，我开始建工程
- 要改直接说改哪儿，我退回去给写稿 agent
```

**要验收时**：
```
──────────── 验收卡 ────────────
门：chapter_gate
产物：work/x/presentation/src/chapters/01-hook
问题：第 1 章的视觉方向对吗？3 步节奏是不是太快？
通过回「过」，我并行做第 2..N 章
──────────────────────────────
```

**人不在时**：不要自己往下推。把当前状态留在 `state.json`（`status=awaiting_user`），
回来后 `python duo.py status --work work/x` 继续。

## 异常处理

| 情况 | 处理 |
|---|---|
| 写稿 agent 不读 skill | 把 `handoff.writer.md` 里的「必读」清单直接贴进对话；仍不读就用 `script-contract.md` 手把手给格式 |
| 审参考度超 60 | 不要自己改稿，退回给写稿 agent，并说清「换结构，不要换词」 |
| 写稿 agent 两次不过 | 降低参考度预算到 30，重新 handoff |
| 执行 agent 卡住 | 看 `state.json` 的 stage；`duo.py status`；不要重开会话（会丢上下文） |
| 音频和 step 对不上 | 改过 `narrations.ts` 就要重跑 extract + synthesize |
| 录屏失败 | 切人工 OBS，不要降低验收标准 |
| 素材不够 | 问人：复用库里的 / 新生成 / 先用占位 |

## 和 trio 模式的差别

| 维度 | 三人模式 | 双人模式 |
|---|---|---|
| 总控 | WorkBuddy（另一个 agent） | 人 |
| 派活 | MCP 自动派 | 执行 agent 生成交接稿，人转发 |
| 等待 | 轮询 job / `get_result` | 当面问一句 |
| 验收卡 | 发到 WorkBuddy 会话，手机也能看 | 直接在对话里给 |
| 远程 | 支持（手机 App + 状态文件） | 不支持（人在电脑前） |
| 适合 | 批量、无人值守 | 边看边调、一次性高质量产出 |
