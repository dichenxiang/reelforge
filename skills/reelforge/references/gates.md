# 五道门（硬流程）

任何片子都必须依次通过。**没有"用户说了不用看"以外的跳过理由**；跳了要把原话抄进 `state.json` 的 `gate_note`。

| # | 门 | 时机 | 交给用户的东西 | 没过会怎样 |
|---|---|---|---|---|
| 1 | `style_gate` | 开工后、写稿前 | 2–3 个风格候选（截图或参考帧）+ 画风/配色/比例/模板 id | 不许写稿 |
| 2 | `script_gate` | 稿子写完 + 审计后 | 口播稿全文 + 分段时长表 + 待拍板的点 | 不许开工 |
| 3 | `pilot_gate` | 正式制作前 | 15–20 秒样片（或第 1 章） | 不许全篇 |
| 4 | `audio_gate` | 配音完成 | 音轨 + 每段实际时长 | 不许录屏/合成 |
| 5 | `final_gate` | 成片完成 | ffprobe + 关键帧 + 简介 | 不许交付 |

## 每道门的固定四步

1. **先写"可验证的断言"**：不是"做好了"，而是"第 32 秒会出现边框+放大条，抽帧可见"。
2. **发一张 ≤10 行的卡**（模板见下）。
3. **用户回"过"或"改哪里"**，把原话和结论写进 `state.json`。
4. **没过就回退**到对应阶段重做，不许带着问题往下走。

## 卡模板

```
阶段：pilot_gate（3/5）
产物：样片 18s  work/demo/pilot.mp4
断言：1 个转场 + 2 个动效 + 3 句字幕 + 1 段配音，全部为最终参数
待定：字幕位置偏下 8px 是否接受
下一步：过 → 启动全篇；改 → 说明改哪里
```

## 1 · 风格门（最容易漏）

- 必须给**候选**，不许默认、不许"我选一个你看"。至少 2 个，最好 3 个。
- 候选要能被看见：模板截图、参考帧、或一帧渲染结果，不能只有文字描述。
- 一并确定：画风（报社/杂志/极简/赛博）、主色、比例、字体气质、是否需要实拍素材。
- 定了写进 `state.json`：`--meta template=<id> --meta style=<name>`。
- **风格门没过，写稿不许开始**——稿子的节奏和视觉方案是绑定的，先写后改风格等于重写。

## 3 · 样片门（最省时间）

样片必须把这些都用**最终参数**跑一遍：

| 要素 | 为什么 |
|---|---|
| 一个转场 | 转场最容易在整片里崩 |
| 一个动效（含放大/推近） | 缓动曲线、边框、层级问题只在动起来时暴露 |
| 一句配音 + 对应字幕 | 验证时间码对齐 |
| 一个音效 | 验证音效是否落在口播结束前 |

样片长度 15–20 秒，覆盖"最复杂的那一段"，不要挑最简单的。

**最小形态（更推荐）**：不做拼盘，直接做**一个完整镜头**——带配音、带字幕、带音效，从入场到出场走完整条。这种样片能暴露真正的接缝问题，拼盘不能。确认后再追加 2–3 个镜头，最后才铺全篇。

**样片不许用临时字体/临时配色**——那样验收没有意义，正式版还得再看一遍。

## 5 · 成片门（机器判据，不靠目测）

`final_gate` 之前必须跑完这四项，任何一项不过都不交付：

| 项 | 判据 | 为什么 |
|---|---|---|
| 时长一致 | \|画面总长 − 旁白总长\| < 0.3s | 时间线改过但旁白没重算，是本片翻车根源 |
| 静止段 | `freezedetect` 扫出 >0.8s 的静止段，逐条对照镜头表豁免 | 分不清「设计上的静帧」和「渲染卡住」 |
| 音效错位 | 每个 cue 与口播包络比对，落在口播结束后 = 失败 | 音效晚于口播是最刺耳的错误 |
| 抽帧网格 | 每个切点前后各 3 帧拼 3×4 一张图 | 一张图看完，比逐张翻快十倍 |

## 记录格式

```bash
python scripts/state.py gate --work work/<slug> --name pilot_gate \
  --artifacts work/<slug>/pilot.mp4
python scripts/state.py meta --work work/<slug> --key gate_note --value "用户：字幕再低 8px"
```
