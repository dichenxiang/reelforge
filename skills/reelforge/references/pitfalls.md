# 踩坑清单（来自《Muse 提示词》一片的实战）

这份文件是**硬规则**，不是经验分享。每条都对应一次真实返工。

## 一、时间轴：只能有一个真相源

| 坑 | 后果 | 规则 |
|---|---|---|
| 按字数比例把总时长分给每句字幕 | 误差累加，越到后面越错，出现"缺句/延迟" | 字幕、动效、音效**全部**取自同一份句子级时间码（每句单独合成、单独计时） |
| 时间线改了，旁白 wav 还在就继续用 | 音画整体错位（本片错 0.7 秒） | 旁白必须校验时长：`abs(旁白时长 - 各段之和) < 0.3`，不符就重算 |
| 字幕 PNG 按文件名缓存 | 文案改了、字幕没变 | 缓存要带输入指纹（文案 + 时长 + 高亮词） |

自查：`|画面总长 - 旁白总长| < 0.3s`，且每个切点的字幕与对应句子同起点。

## 二、合成：显隐不等于时间

| 坑 | 现象 | 规则 |
|---|---|---|
| 用 `overlay … enable=gte(t,T)` 控制出场 | 素材从 0 秒就在走，出场时已经播到 T 秒后的画面 | 要让素材"从某处开始"，必须给素材本身加时间偏移 `setpts=PTS+T/TB`，enable 只管显隐 |
| 为了省解码把每路输入裁短 | 串行叠图被最短的一路截断，后几层直接不出现 | 叠图输入的时长一律给足整段，**不要**按"露脸时长"裁 |

## 三、验证：参数 ≠ 结果

| 坑 | 现象 | 规则 |
|---|---|---|
| 改了 `ss` / 坐标 / 颜色就宣布修好 | 用户看到的还是错的 | 每次改完**抽一帧**和预期对比，再说话 |
| 坐标靠猜 | 放大框圈到了上一行 | 先出带网格的参考帧量坐标，别估 |
| 一次改多个变量 | 出错无法定位 | 一次只改一个，改完立即验 |

**交付前必查**：时长、首尾帧、每个切点的前三后三帧、音画偏移、字幕与句子的起点一致性。

## 四、需求：模糊词必须翻译成断言

| 用户说法 | 错误的做法 | 正确做法 |
|---|---|---|
| "用第 2 秒开始的一小段" | 加慢放、加定格、裁短 | 复述："从源文件 2.0 秒起，原速，播满它的出镜时长" |
| "紧凑一点" | 随便砍 10 秒 | 问清楚砍段还是砍停顿（停顿通常先砍） |
| "效果库" | 只写文档 | 落成可执行的 CLI + 基准帧 |

**同一个点被说第三次，就是我的理解模型错了，不是参数错了**——停下来复述，不要继续调参。

## 五、我方常犯（自检）

1. **过度设计**：加慢放、加定格、加没人要的特效。默认不加。
2. **说得太满**："修好了""这次对了"，但没验证到用户关心的那一点。
3. **只验参数不验像素**。
4. **缓存陈旧**（"文件在"就当"内容对"）。
5. **一次改一大片**，重建几分钟，于是懒得验。

## 六、开工前的三句话

跑任何一条片子之前，先回答：

1. 这条片子的时间真相源是什么？（哪份文件/哪个脚本产出）
2. 改一处之后，我用什么**一帧证据**证明改对了？
3. 这次要新写哪些动效？交付前它们怎么进效果库、怎么被自动调用？

## 七、效果库与自动匹配（批次 3/4 实测新增）

| 坑 | 现象 | 规则 |
|---|---|---|
| 只认本地 `index.json` | 仓库新增 19 个效果，本机自检只看到 13 个 | 本地 + 仓库合并，按 id 去重，**仓库条目优先**；模块解析也仓库优先 |
| `entry` 带 `:函数名` 当整串路径 | `check` 误报所有可运行效果文件缺失 | 取 `partition(":")[0]`，冒号后是函数名 |
| 写死 `"ffmpeg"` | agent 会话 PATH 不含 ffmpeg，全部片段 `FileNotFoundError` | 用 `runtime.ffmpeg_bin()`；项目侧补 PATH 必须在 `import vid` 之前 |
| 自动匹配塞整句进文本效果 | 成片开头「同样一」被裁掉，只剩「个 Muse，为什么…」 | 文本效果一律 `_fit_font` 自动缩字号；长 label 与数字要拉开 y，别重叠 |
| 拿 `target` 宽高当文字区 | `index_badge` 的 target 宽 0，句子被折成一条竖排单字串 | 标注类文字用固定 `text_box`，不用 target |
| 纯关键词打分 | 设问句被配到堆叠条，号召句被配到折线图 | 先按节拍白名单圈候选，数据类再加准入门；低置信回基础文字动效 |
| 转场没给 `a`/`b` | 出来的片段是「未提供 a_img / b_img」占位帧，还以为渲染成功 | 镜头表里必须带前后帧路径；抽帧失败要报错，不要静默占位 |
| 效果只躺在库里 | 做片子时还得人手描述动效，用户反复返工 | 镜头表能直接写 `("fx", ...)`，`plan` 能自动出表；交付前必须验证「稿子 → 片段」跑通并抽帧看 |

**「能跑」不等于「接上了」**：全库 `check` 全绿只是第一层，必须再用真实稿子
跑一遍 `plan → render → 抽帧`，看见画面里真的有自动配上的动效，才算交付。
