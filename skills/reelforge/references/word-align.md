# 字级时间戳（可选增强）

目标：把「字幕/动效/音效按句对齐」升级为「按字对齐」。句子级够用，但关键词高亮、放大镜出现点、音效落点都需要更细的锚。

## 为什么值得做

现在的时间码来自逐句合成：每句一个音频，句子内部的字没有时间信息。于是：

- 关键词高亮只能整句一起亮
- 「光线？机位？人物表情？」这类并列句，三个气泡只能等间隔弹
- 音效 cue 只能挂在句首

字级对齐后，这些都能锚到确切的字。

## 输入输出

```
输入  script.md（或句子列表）+ narration.wav（同一份配音）
输出  timing.json
```

```json
{
  "audio": "narration.wav",
  "duration": 76.46,
  "backend": "faster-whisper",
  "words": [
    {"t": "同", "s": 0.42, "e": 0.58},
    {"t": "样", "s": 0.58, "e": 0.71},
    {"t": "一", "s": 0.71, "e": 0.80}
  ],
  "sentences": [
    {"text": "同样一个 Muse…", "s": 0.42, "e": 3.10, "first_word": 0, "last_word": 19}
  ]
}
```

- `words` 按时间升序，`s/e` 为秒，保留三位小数
- `sentences` 保留句子级索引，便于回退
- 文本必须和实际朗读一致（数字、英文缩写要先归一化成读法）

## 后端选择

| 后端 | 依赖 | 特点 |
|---|---|---|
| faster-whisper（推荐先试） | `pip install faster-whisper` | 免手动下模型，CPU 可跑，中英混排稳 |
| FireRedASR2-CTC（sherpa-onnx） | 首次下模型约 700MB | 中文精度更好，离线 |
| 逐字 SRT（人工/其他工具） | 无 | 兜底，任何情况下都能用 |

精度参考（业界实测）：字级偏差中位 20–40ms，最差约 200ms。对字幕足够，对「卡在鼓点上」的音效也够。

## 接入点

1. `make.py` 的 `build_parts()` 之后跑一次对齐，写 `_build/timing.json`
2. 字幕：优先用 `words` 切行（按标点 + 最大字数），时间取首字 `s` / 末字 `e`；失败回退句子级
3. 动效 beats：`{"anchor": "人物表情？"}` 这种写法，由 timing 解析成秒，不再写死比例
4. 音效 cue：同样按词锚，而不是按 `adur * 0.55`

## 失败与降级

- 对齐文本与实际朗读不一致（漏字、改词）：**只告警不中断**，该句回退句子级时间
- 音频过长（>10 分钟）：分段对齐再拼接，避免一次性占满内存
- 没有模型 / 装不上依赖：直接跳过，管线照常跑（这项是增强，不是依赖）

## 验收

- 随机抽 10 个字，人工听 ±150ms 是否落在字内
- 全片字幕起点与音频起点偏差 < 80ms
- 音效 cue 不得落在口播结束之后（这是硬失败）
