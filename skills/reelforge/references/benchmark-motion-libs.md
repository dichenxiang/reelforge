# 三个动效库的评估（能不能进我们的流）

评估时间：2026-11。只看「对我们这条 Python + ffmpeg + wvp 管线有没有用」，不看星数。

## 一句话对照

| 仓库 | 是什么 | 技术栈 | 许可 | 能否直接用代码 |
|---|---|---|---|---|
| [hyperframes](https://github.com/heygen-com/hyperframes) | HTML 写、无头 Chrome 渲、FFmpeg 出片；带 ~450 个可安装块和 `frame.md` 设计令牌层 | Node + Puppeteer + GSAP | **Apache-2.0** | 可以，但栈不匹配 |
| [video-shotcraft](https://github.com/Vincentwei1021/video-shotcraft) | 产品宣传片；124 张配方卡 / 150 个镜头；抓真实页面、卡点剪辑 | Remotion（React） | 代码 Apache-2.0 | 可以，但栈不匹配 |
| [video-talkcraft](https://github.com/Vincentwei1021/video-talkcraft) | 口播视频；**字级同步 + 108 张卡 + 七层反 PPT + 三重验收** | Remotion（React） | **PolyForm 非商业** | **不可以**（商用需授权） |

**许可说明**：talkcraft 是「个人/教育/研究免费，商业需授权」——**自用不受影响**，只有将来商用或对外分发才需要处理。shotcraft、hyperframes 是 Apache-2.0。所以自用场景下三家的代码都能拿。

**真正的门槛不是许可，是技术栈**：我们自己的 wvp 是 **Vite + React + TS**，shotcraft / talkcraft 是 **Remotion（React）**——同一门语言，组件层能直接对接。hyperframes 是纯 HTML + GSAP，也能用 iframe 或改写引入。

## 值得吸收的六件事（按 ROI 排序）

### 1. 字级时间戳（最高价值）

- **他们怎么做**：`timestamps_cpu.py` 用 FireRedASR2-CTC 或 faster-whisper 在本地把稿子对齐到音频，字级偏差中位 20–40ms；每个动效节拍锚在**确切的字**上。
- **我们现状**：句子级逐句合成计时，节拍只能落在句首。关键词高亮和放大镜的出现点，精度就是一句话。
- **怎么落**：新增 `scripts/align.py`，后端 faster-whisper（CPU 可跑），输入 `稿子 + 成品 wav`，输出 `timing.json`（逐字起止）。字幕、音效 cue、动效 beats 全部改读它；句子级时间码退化为「兜底」。
- **代价**：首次要下模型（几百 MB），跑一遍约等于音频时长的 0.2×。可选增强，不阻塞主流程。

### 2. 配方卡格式（几乎零成本）

- **他们怎么做**：每张卡 = **意图 + 能量档 + 参数 + 实现要点 + 已知坑 + 自包含源码 + 可跑预览**，另有画廊一页全览、按输入类型索引。
- **我们现状**：`index.json` 只有 id / title / tags / entry / baseline。缺「什么时候该用它」「哪里容易翻车」。
- **怎么落**：给 index 加 `intent / energy / inputs / pitfalls / preview`；`effects.py card <id>` 输出一页卡片；`list` 按 energy 或 inputs 过滤。
- **代价**：改 CLI + 迁移现有 10 条，半小时级。

### 3. 三重验收（补我们的 QC 盲区）

- **他们怎么做**：① 画面健康双判定——静止段检测 + 并发光栅抖动；② 纯音效轨逐 cue 能量验证；③ 独立评审看拼图。
- **我们现状**：QC 只有时长一致、首帧、抽帧目检。**没有机器判据**，全靠我肉眼看几张图——这次反复返工正撞在这上面。
- **怎么落**：`scripts/qc.py`
  - `freezedetect` 扫全片，标出 >0.8s 的静止段（合法静帧要在镜头表里登记豁免）
  - 音效 cue 与口播包络比对：cue 落在口播结束后 = 错位
  - 关键切点前后各抽 3 帧拼 3×4 网格，一次看完

### 4. 首镜先做先确认（我们已有，可加一条）

- **他们怎么做**：先搭全合成骨架、其余镜头占位，只做一个样板镜，用 `--seg-audio` 出**有声单镜预览**给用户确认，再铺开。
- **我们现状**：`pilot_gate` 已经是这个思路，但样片是「15–20 秒拼起来的」，不如「一个完整镜头、带声、带字幕」来得有说服力。
- **怎么落**：gates.md 里把 pilot 的最小形态定为「1 个镜头 + 声 + 字幕 + 音效」，可再加 2 个镜头。

### 5. 分段渲染母版制（省时间）

- **他们的做法**：按镜头切段并行渲，改一个镜头只重渲该段 ± 邻段。
- **我们现状**：段级缓存有，但**时间线一变就全量失效**（这次开场加 0.7 秒，导致音画错位就是这么来的）。
- **怎么落**：缓存键从 `id` 改成 `hash(该段所有输入 + 参数 + 起始时间)`；时间线变化只让受影响的段失效。

### 6. 容器边框八式（视觉资产）

- **他们怎么做**：单视频镜头必须包一式主题边框——浏览器窗 / 胶片 / 拍立得 / 图纸等八式，一片一式。
- **我们现状**：只有「显示器边框」一式，是这次现写的。
- **怎么落**：把 `frame_zoom` 的边框抽成 `frame` 参数（bezel 样式 + 半径 + 阴影 + 标签位），先做 4 式够用。

## 三条融合路径（按成本排序）

| 路径 | 怎么做 | 成本 | 适合 |
|---|---|---|---|
| **① 透明通道当素材** | 在 Remotion 工程里单独渲一张卡，导出 ProRes 4444 / VP9 alpha，我们 ffmpeg overlay 叠到 PIL 画面上 | 极低，零改造 | 现在就能用，先把好看的卡吃进来 |
| **② 卡改造成 wvp 组件** | 把 `template/cards/*.tsx` 搬进 wvp，替换 3 个 Remotion API（`useCurrentFrame` / `interpolate` / `spring`）→ 改读 wvp 的 step 进度 | 每张 0.5–1 小时 | 想长期沉淀成自己的组件库 |
| **③ 换渲染栈到 Remotion** | 整个管线改成 Remotion 工程 | 高，等于重写 | 不建议 |

**② 为什么可行**：Remotion 组件本质上就是「输入帧号、返回 JSX」的纯函数。wvp 是「点击推进节拍」，把节拍映射成 0→1 的进度，代入同一套插值就能跑。需要替换的只有：

| Remotion API | 替换成 |
|---|---|
| `useCurrentFrame()` | 当前 step 的进度 × 目标帧数 |
| `interpolate(frame, [a,b], [c,d])` | 自己写 20 行，支持多段 + easing |
| `spring({frame, fps})` | 换成 `easeOutBack` 之类的缓动函数 |
| `<AbsoluteFill>` / `<Sequence>` | `div` + 条件渲染 |

**①为什么最省**：talkcraft 的工作台支持右键导出单段透明视频（MOV ProRes 4444 / WebM VP9）。拿到带 alpha 的片段后，我们现有管线一行 ffmpeg 就能叠，不改任何代码。

## 不引入的部分

| 内容 | 原因 |
|---|---|
| 整体切换渲染栈 | 我们已有 wvp（React）+ PIL 双管线；局部接组件就够，不必推倒 |
| 全量搬 108 / 124 张卡 | 视觉语言不匹配（他们是 Apple 范式产品片，我们是报纸版式），按需挑 10–20 张改造即可 |
| `frame.md` 全量体系 | 值得抄的是**思路**（风格门产出给镜头用的令牌），不是那套文档结构 |
| 云端渲染 / Lambda | 本地够用 |

## 落地顺序

1. **配方卡字段**（半小时，立刻改善效果库可用性）
2. **qc.py 的静止段 + 音效错位检测**（半天，直接堵住这次返工的根因）
3. **缓存键改成输入指纹**（半天，消灭「改了没生效」）
4. **字级对齐**（一天，字幕/节拍精度从「句」到「字」）
5. 容器边框扩到 4 式（一天，视觉资产）

第 1–3 项是**修机制**，第 4–5 项是**提上限**。先修机制。
