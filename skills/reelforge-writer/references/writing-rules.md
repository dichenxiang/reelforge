# 口播稿规则

方法论来源：wvp 的 `references/SCRIPT-STYLE.md`（MIT）+ 中文去 AI 味的通行做法，
按「16:9 一屏一步」重写。**规则是硬约束，不是建议。**

## 一、信息保留

- 原文信息保留 **≥60%**，删减不超过 40%
- 删的是形容词、重复结论、背景铺陈；**数字、对比、结论不能删**
- 写完自查：原文的每个关键数字/结论，稿子里还能不能找到

## 二、八个形式原则

1. **口语化**：书面词换成「说出来不别扭」的说法
   - ✗ 该产品具备卓越的性价比优势 → ✓ 这价格，这分数，有点不讲道理
2. **短句**：每句 ≤20 字；长句拆成两句，别用「并且/此外/因此」硬接
3. **第二人称**：多用「你 / 我们」，少用「用户 / 读者 / 消费者」
4. **开头有钩子**：第一句就给冲突、数字或反常识，不铺垫
5. **节拍用 `---` 分隔**：一个 `---` = 一个完整想法 = 一个 step
6. **数字翻译成感受**：52% 提升 → 快了一半；1999 元 → 一台中端机的钱
7. **不堆结构词**：「首先/其次/最后」「值得注意的是」一律删
8. **具体例子优先**：说「跑分翻倍」不如说「同一局游戏，帧数从 60 到 118」

## 三、五类 AI 腔，见一个删一个

| 类型 | 长什么样 | 怎么改 |
|---|---|---|
| 假共情 | 「我懂你的纠结」「说实话，我也曾……」 | 直接给结论或事实 |
| 假深刻 | 「恰恰 / 反而 / 正是」包装平庸观点 | 去掉副词，说人话 |
| 自我标榜 | 「作为一个专业测评人……」 | 删掉身份，留证据 |
| 万能模板 | 「在当今这个……时代」「不得不说」 | 删 |
| 排比堆砌 | 连续三句同结构 | 打散，长短交错 |

## 四、屏幕文字

- 主标题 ≤14 个汉字，副标 ≤20 个
- 一屏只讲一件事；超过就拆成两个 step
- 不要把口播稿整句抄上屏——屏幕是「结论」，不是「字幕」

## 五、参考片怎么借（默认 40 分，上限 60）

| 层 | 可借 | 不可借 |
|---|---|---|
| 结构 | 开场冲突 → 拆 2–3 点 → 落点；段落比例 | 逐镜头翻拍 |
| 手法 | 最多 2 个标志性动作（如数字滚动、对比条） | 全套视觉包装 |
| 文案 | 无 | 任何原句、同义替换句 |

自检：
```bash
python <reelforge>/scripts/similarity.py --work <work> --target 40 --max 60
```
超 60 就重写结构，不要只换词。

## 六、交付前清单

- [ ] 第一句 3 秒内出现冲突/数字/反常识
- [ ] 每拍 ≤14 字上屏，`---` 数量 = 步数
- [ ] 所有数字有来源（`source_basis` 写明）
- [ ] 没有「最/第一/必买/全网」
- [ ] 相似度审计通过
- [ ] `script.json` 的 `visual` 写的是「变化」，不是「元素」
